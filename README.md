# stm32_load_pwm

Компактная C-библиотека для управления яркостью/мощностью произвольной ШИМ-нагрузки на STM32
(включая младшие МК без аппаратного FPU, например STM32F030): светодиоды с гамма-коррекцией и
линейная нагрузка (лампы накаливания, кулеры, DC-моторы, электромагниты) — циклы индикации, плавные
переходы и настраиваемые уровни качества Flash/RAM, без malloc и без блокировок.

## Возможности

Часто нужно управлять яркостью/мощностью нагрузки не тупым вкл/выкл, а плавно или по красивому
циклу — но реализовывать таймеры, фазовые аккумуляторы и гамма-коррекцию под каждый проект заново —
рутина. Библиотека берёт это на себя:

- Регистрация произвольного числа нагрузок через `LOAD_PWM_Init()`, каждая — со своим типом
  (`LOAD_PWM_TYPE_LED` / `LOAD_PWM_TYPE_LINEAR`).
- **Гамма-коррекция для светодиодов**, откалиброванная под ваше железо: три опорных уровня
  скважности ШИМ (0%, ~50%, 100% визуальной яркости). Не хотите измерять точку 50% — задайте
  отрицательное значение, и библиотека применит типовую gamma (2.2) вместо калибровки по факту.
- **Линейный режим для прочей нагрузки** (лампы, кулеры, моторы, электромагниты) — скважность ШИМ
  пропорциональна заданному значению напрямую, без гамма-коррекции и без калибровочной таблицы
  вообще.
- 8 готовых циклов индикации на константных таблицах: меандр, "дыхание", импульс с ожиданием,
  полутрапеция, полупила, треугольник, двойной проблеск, строб.
- Зацикленный запуск, однократный запуск и остановка цикла — с настраиваемым сдвигом по фазе.
- Фоновая яркость с опциональным плавным переходом между значениями фона.
- **`LOAD_PWM_StopAll()`** — аварийный сброс всех нагрузок разом.
- **`LOAD_PWM_SetGlobalBrightness()`** — глобальный "ночной" множитель для всех нагрузок сразу,
  накладывается после гамма-коррекции.
- **Не привязана к главному таймеру**: обновление — вызовом `LOAD_PWM_Tick(tick_source_id)` из
  прерывания, main-loop или RTOS-задачи, с любой периодичностью, примерно соответствующей заявленной
  частоте.
- **Настраиваемые уровни качества** (см. раздел ниже) — выбор компромисса Flash/RAM под конкретный
  проект и МК.

## Требования к настройке в CubeMX

- **Таймер(ы) нагрузок**: соответствующий канал в режиме PWM Generation, частота ШИМ — без видимого
  мерцания/жужжания (обычно от 1 кГц), ARR — по вкусу. Отдельного "главного" таймера настраивать не
  нужно.
- Явно вызывать `HAL_TIM_PWM_Start` не нужно — библиотека делает это сама при регистрации.
  Периодичность вызова `LOAD_PWM_Tick()` обеспечиваете вы сами — любым удобным способом.

## Быстрый старт

```c
#include "stm32_load_pwm.h"

LOAD_PWM_Handle_t *status_led;
LOAD_PWM_Handle_t *cooling_fan;

void LoadsInit(void)
{
    /* Светодиод - с типовой гаммой (точку 50% не измеряли) */
    LOAD_PWM_Config_t led_cfg = {
        .tick_source_id = 0,       /* группа "тикающая" из таймера htim6 */
        .tick_freq_hz   = 1000,    /* 1000 Гц - реальная частота ваших вызовов LOAD_PWM_Tick(0) */
        .htim           = &htim3,
        .channel        = TIM_CHANNEL_1,
        .load_type      = LOAD_PWM_TYPE_LED,
        .brightness_min_percent = 0.0f,
        .brightness_mid_percent = -1.0f,   /* не измеряли - типовая gamma 2.2 */
        .brightness_max_percent = 100.0f,
    };
    status_led = LOAD_PWM_Init(&led_cfg);

    /* Кулер охлаждения - линейная нагрузка, та же группа тика */
    LOAD_PWM_Config_t fan_cfg = {
        .tick_source_id = 0,
        .tick_freq_hz   = 1000,
        .htim           = &htim4,
        .channel        = TIM_CHANNEL_1,
        .load_type      = LOAD_PWM_TYPE_LINEAR,
        .brightness_min_percent = 0.0f,
        .brightness_mid_percent = -1.0f,   /* игнорируется для LINEAR */
        .brightness_max_percent = 100.0f,
    };
    cooling_fan = LOAD_PWM_Init(&fan_cfg);
}

void OnDeviceOk(void)
{
    LOAD_PWM_Start(status_led, LOAD_PWM_CYCLE_BREATH, 0.0f, 2000);
    LOAD_PWM_SetBrightness(cooling_fan, 40.0f, 0); /* кулер на 40% мощности */
}
```

```c
/* Периодическое обновление - здесь из прерывания таймера, но с тем же
   успехом можно вызывать из while(1) в main() или из задачи RTOS */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim == &htim6)
    {
        LOAD_PWM_Tick(0); /* группа tick_source_id = 0, см. LoadsInit() выше */
    }
}
```

## Настройка памяти: два независимых уровня качества

Библиотека даёт выбрать компромисс между потребляемой памятью и качеством ШИМ по двум независимым
осям, задаваемым через `#define` до включения `stm32_load_pwm.h` (например в вашем `main.h`). Если
ничего не задано — используются значения по умолчанию (максимальное качество).

### `LOAD_PWM_TABLE_QUALITY` — разрешение формы циклов (влияет на Flash)

Таблицы формы циклов (меандр/дыхание/трапеция/...) общие для всех нагрузок — расход Flash не зависит
от количества зарегистрированных нагрузок, только от выбранного уровня:

| Значение | Точек/цикл | Код + 8 таблиц циклов (оценка) |
|---|---|---|
| `0` (LOW) | 32 | ~3.35 КБ |
| `1` (MEDIUM) | 64 | ~3.6 КБ |
| `2` (HIGH, по умолчанию) | 128 | ~4.1 КБ |

### `LOAD_PWM_RAM_QUALITY` — тип скважности и точность гамма-кривой (влияет на RAM)

Определяет тип хранения скважности ШИМ (`LOAD_PWM_Duty_t`) и число точек интерполяции гамма-кривой
для LED. В отличие от таблиц циклов, расход RAM масштабируется с количеством нагрузок:

```
RAM = LOAD_PWM_MAX_LOADS * <размер хэндла>  +  LOAD_PWM_MAX_LEDS * <размер LED LUT>
```

| Значение | Тип скважности | Точек LUT | Хэндл (оценка) | LED LUT (оценка) |
|---|---|---|---|---|
| `0` (LOW) | `uint8_t` | 8 | ~44Б | ~9Б |
| `1` (MEDIUM) | `uint16_t` | 16 | ~48Б | ~34Б |
| `2` (HIGH, по умолчанию) | `uint32_t` | 32 | ~56Б | ~132Б |

Выбор `uint8_t`/`uint16_t` ограничивает максимальное число ступеней ШИМ до предела этого типа
(255/65535), независимо от реального ARR таймера — сознательный компромисс ради экономии RAM.

### Раздельные пулы: нагрузки и LED-калибровка

Таблица гамма-коррекции нужна ТОЛЬКО светодиодам — линейная нагрузка считается по точной формуле без
всякой таблицы. Поэтому `LOAD_PWM_MAX_LEDS` задаётся отдельно от `LOAD_PWM_MAX_LOADS`: если в
проекте, например, 8 нагрузок, но только 4 из них — LED, задайте `LOAD_PWM_MAX_LEDS = 4`, чтобы не
платить RAM за калибровку, не нужную остальным четырём.

```c
/* пример: 4 светодиода + 4 DC-мотора, компромиссный уровень качества */
#define LOAD_PWM_MAX_LOADS    8
#define LOAD_PWM_MAX_LEDS     4
#define LOAD_PWM_TABLE_QUALITY 1
#define LOAD_PWM_RAM_QUALITY   1
#include "stm32_load_pwm.h"
```

Для этого примера суммарный расход памяти ориентировочно: Flash ~3.6 КБ, RAM ~48×8 + 34×4 ≈ 520
байт.

## Честные ограничения

- Гамма-кривая для LED — единая степенная функция `x^gamma`, откалиброванная по одной измеренной
  точке (или типовому значению) — разумное приближение, а не физически измеренная кривая всего
  диапазона.
- Набор циклов фиксирован восемью формами — своя произвольная форма потребует добавить таблицу в
  `stm32_load_pwm.c`.
- Плавный переход (`fade_ms`) работает только между фоновыми значениями, когда простаивает —
  переходы цикл↔фон всегда мгновенные.
- `LOAD_PWM_Tick()` не отслеживает реальное прошедшее время — точность цикла зависит от того,
  насколько стабильно вы вызываете её с заявленной `tick_freq_hz`.
- Уровни `LOAD_PWM_TABLE_QUALITY`/`LOAD_PWM_RAM_QUALITY` ниже HIGH — компромисс: более грубая форма
  циклов и/или более грубое разрешение ШИМ/гамма-кривой.
- Разрешение `LOAD_PWM_SetBrightness()` для `LOAD_PWM_TYPE_LED` ограничено 256 шагами (разрешение
  самой интерполяции по гамма-LUT) — для `LOAD_PWM_TYPE_LINEAR` ограничения нет, используется полное
  разрешение диапазона `pwm_min..pwm_max` независимо от `LOAD_PWM_RAM_QUALITY`.
- Циклы индикации (`LOAD_PWM_Start`/`StartOnce`) для ЛЮБОГО типа нагрузки читают форму из общей
  таблицы 0..255 — 256 шагов достаточно для плавности визуально/на слух.
- `LOAD_PWM_Tick()` обычно вызывается из прерывания таймера, тогда как остальные функции API — из
  основного потока/задачи RTOS. Обычный сценарий (вся настройка через `LOAD_PWM_Init()` на старте,
  до включения прерывания с `Tick()`) в дополнительной защите не нуждается; повторный `Init()` уже
  активной нагрузки не из того же контекста, что и её `Tick()`, требует критической секции
  (`__disable_irq()`/`__enable_irq()`) от вас — подробности в шапке `stm32_load_pwm.h`.
- Все процентные (`float`) параметры API безопасно обрабатываются даже при `NaN` на входе
  (неинициализированная переменная, битый датчик) — клампятся к 0..100. Некорректные ссылки на
  несуществующий хэндл (не полученный от `LOAD_PWM_Init()`) библиотека, как и большинство
  C-библиотек, отследить не может — это ответственность вызывающего кода.
- Групповые "бегущие" эффекты, RGB-обёртка, калибровка "на лету" и хранение калибровки в
  энергонезависимой памяти — сознательно не реализованы (см. `Список_идей.md`).
