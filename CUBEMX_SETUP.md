# Настройка CubeMX для stm32_load_pwm

Развёрнутое описание настроек периферии, от которых зависит корректная работа библиотеки. Краткая
сводка — в README.md, раздел "Требования к настройке в CubeMX". При расхождениях ориентируйтесь на
смысл параметров ниже, а не на конкретные цифры примеров.

## Таймер(ы) нагрузок (TIMx, канал CHy)

Для каждого `htim`/`channel`, который вы передаёте в `LOAD_PWM_Config_t`, в CubeMX на вкладке
таймера нужно настроить соответствующий канал в режим **PWM Generation CHy** (Mode → PWM Generation
No Output / Output сравнение неважно, важен сам режим PWM на канале).

Библиотека сама вызывает `HAL_TIM_PWM_Start()` при регистрации нагрузки (`LOAD_PWM_Init()`) —
вручную запускать канал не нужно и не нужно включать прерывание по этому таймеру ради самой
библиотеки (прерывание нужно только вам отдельно — для периодического вызова `LOAD_PWM_Tick()`).

| Параметр CubeMX | Допустимый диапазон | Рекомендуемое значение для этой библиотеки | Пояснение |
|---|---|---|---|
| **Prescaler (PSC)** | 0..65535 | Подбирается вместе с ARR по формуле ниже | Делитель частоты тактирования таймера перед счётчиком. |
| **Counter Period (ARR)** | 1..65535 (16-бит таймеры) / больше для 32-бит таймеров | Подбирается вместе с PSC по формуле ниже | Определяет и частоту ШИМ, и аппаратное разрешение скважности (число шагов 0..ARR). |
| **PWM Mode** канала | PWM Mode 1 / PWM Mode 2 | PWM Mode 1 | Полярность заполнения — Mode 1 даёт активный уровень пока `CCRx < CNT`, привычная и ожидаемая библиотекой логика нарастания скважности с ростом заданного процента. |
| **CH Polarity** | High / Low | High | Если используется инвертирующий драйвер нагрузки — можно выставить Low, библиотека от этого не зависит (она работает в процентах заполнения, а не в уровнях), но для предсказуемости по умолчанию держите High. |
| **Auto-reload preload** | Enable / Disable | Enable | Исключает дребезг скважности при обновлении `CCRx` на лету (библиотека переустанавливает скважность при каждом вызове `LOAD_PWM_SetBrightness`/цикле). |

### Формула частоты ШИМ

```
f_PWM = f_TIM_CLK / ((PSC + 1) * (ARR + 1))
```

где `f_TIM_CLK` — частота тактирования таймера (смотрите Clock Configuration в CubeMX для
конкретного TIMx — APB1/APB2 таймерная шина, с учётом множителя x2 если APB-предделитель ≠ 1).

**Рекомендация для этой библиотеки**: `f_PWM` от **~1 кГц и выше** — ниже заметно мерцание (для
`LOAD_PWM_TYPE_LED`) или слышимое жужжание (для `LOAD_PWM_TYPE_LINEAR`, например моторы/кулеры).
Верхней границы библиотека не ставит — выбирайте по драйверу нагрузки (многие MOSFET/LED-драйверы
нормально работают до десятков кГц), но учитывайте следующий пункт про разрешение.

### Разрешение скважности (ARR) и `LOAD_PWM_RAM_QUALITY`

Аппаратное разрешение канала — `ARR + 1` шагов. Библиотека дополнительно ограничивает число шагов
сверху типом `LOAD_PWM_Duty_t`, который зависит от `LOAD_PWM_RAM_QUALITY`:

| `LOAD_PWM_RAM_QUALITY` | Тип `LOAD_PWM_Duty_t` | Максимум шагов |
|---|---|---|
| `0` (LOW) | `uint8_t` | 255 |
| `1` (MEDIUM) | `uint16_t` | 65535 |
| `2` (HIGH, по умолчанию) | `uint32_t` | 4294967295 |

Если ARR канала больше этого предела — лишнее аппаратное разрешение просто не используется (не
ошибка, но и не даёт выигрыша). Поэтому для LOW/MEDIUM нет смысла держать ARR больше 255/65535
соответственно — компромисс между PSC и ARR стоит сдвигать в сторону ARR ≈ предел типа, а остаток
делителя частоты — в PSC. Для HIGH подбирайте ARR свободно под нужную `f_PWM` по формуле выше.

## Что НЕ требуется настраивать

- Отдельный "главный"/ведущий таймер для `LOAD_PWM_Tick()` библиотека не предписывает — периодичность
  вызова `LOAD_PWM_Tick(tick_source_id)` вы обеспечиваете сами любым удобным способом (отдельный
  TIMx с прерыванием, SysTick, задача RTOS) — настройка этого источника вне области данного файла.
- One Pulse Mode, Encoder Mode, Input Capture и прочие режимы таймера библиотеке не нужны — только
  базовый PWM Generation на используемых каналах.
